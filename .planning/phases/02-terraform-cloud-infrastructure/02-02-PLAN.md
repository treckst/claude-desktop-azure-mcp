# Plan 2-02: Azure Storage Infrastructure, Identity RBAC, and Outputs

## Objective
Define the declarative Azure resources in `terraform/main.tf` including Resource Group, Storage Account (LRS, TLS 1.2, flat blob storage), Blob Container, Blob upload of `client_telemetry.csv`, User Assigned Managed Identity, and least-privilege `Storage Blob Data Reader` RBAC assignment, followed by structured outputs in `terraform/outputs.tf`.

## Code Patterns (Model Resilience)
Conventions:
- In `main.tf`:
  - Declare required providers: `azurerm` (~> 3.0 / ~> 4.0) and `random` (~> 3.5).
  - Configure `provider "azurerm" { features {} }`.
  - Use `random_string` (lowercase, numbers only, length 6) to construct a valid unique storage account name: `${var.storage_account_prefix}${random_string.sa_suffix.result}`.
  - Set `min_tls_version = "TLS1_2"` and `is_hns_enabled = false` on `azurerm_storage_account`.
  - Create `azurerm_storage_container` with `container_access_type = "private"`.
  - Create `azurerm_storage_blob` pointing to `"${path.module}/client_telemetry.csv"` with `content_md5 = filemd5("${path.module}/client_telemetry.csv")`.
  - Create `azurerm_user_assigned_identity` named `var.managed_identity_name`.
  - Assign `role_definition_name = "Storage Blob Data Reader"` via `azurerm_role_assignment` scoped to the storage account (`scope = azurerm_storage_account.telemetry_storage.id`).
- In `outputs.tf`:
  - Export `storage_account_name`, `storage_container_name`, `primary_blob_endpoint`, `managed_identity_client_id`, and `telemetry_blob_url`.
